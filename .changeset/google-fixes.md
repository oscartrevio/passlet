Google Wallet fixes, verified against Google's reference docs. New `PassTemplate.sendMessage(serialNumber, message)` adds a message to an issued pass through Google's AddMessage API, the only way Google documents a `TEXT_AND_NOTIFY` push (at most 3 per pass per day). `publish()` now clears class options the template no longer sets (hero image, messages, app link, Smart Tap issuers, locations, modules) and sends `enableSmartTap: false` to turn Smart Tap off. Classes are always written with `reviewStatus` `DRAFT` or `UNDER_REVIEW`, the only values Google accepts on insert and update. Concurrent first issues from a new template no longer fail with `GOOGLE_CONFLICT`. Access tokens are cached for the `expires_in` Google returns, and a cached token Google rejects with 401 is replaced and the request retried once. Template IDs Google cannot use in a class ID now throw `PASS_CONFIG_INVALID` at construction, and air boarding passes missing flight details throw `GOOGLE_FLIGHT_MISSING_CLASS_FIELDS` at construction instead of on first issue; `expire()` checks the serial number too. Gift card balances are converted to micros exactly and a non-decimal balance throws `CREATE_CONFIG_INVALID` before any request; the balance currency falls back to the balance field's `currencyCode`. Loyalty and offer classes carry `localizedProgramName`, `localizedTitle`, `localizedProvider`, and every class `localizedIssuerName` from `locales.<lang>.name`.
